# Объяснение лабораторной простыми словами

## 1. Что мы сделали

Это маленький интернет-магазин, который работает на вашем компьютере.
Администратор добавляет, редактирует и удаляет товары. Покупатель видит товары,
выбирает количество и оформляет заказ. Деньги никуда не переводятся:
«оформить заказ» здесь означает записать строку в базу данных.

Всё разделено на понятные части:

```text
Браузер: показывает страницу и отправляет заполненную форму
    ↓ HTTP-запрос к 127.0.0.1
Flask в app.py: выбирает нужную функцию
    ↓
patterns.py: проверяет права или оформляет заказ
    ↓
database.py / SQLite: читает и записывает store.db
    ↓
Flask подставляет данные в HTML-шаблон
    ↓ HTTP-ответ
Браузер показывает готовую страницу
```

`127.0.0.1` означает «этот же компьютер». `5000` — номер порта, то есть адрес
конкретного приложения на компьютере. Сервер здесь — запущенная программа Python.
Отдельный сервер покупать не нужно.

## 2. Кто за что отвечает

**Python** — язык, на котором написаны проверки, расчёты и работа с данными.

**Flask** — библиотека, которая принимает запрос браузера и вызывает нашу функцию.
Например, запрос `/orders` вызывает функцию `orders()`.

**SQLite** — база данных в одном файле `store.db`. Не надо запускать отдельную
программу для базы. `sqlite3` уже встроена в Python.

**HTML** — структура страницы: заголовки, формы, таблицы, кнопки.

**CSS** — оформление: цвет, отступы, размеры, расположение карточек.

**Jinja** — шаблонизатор Flask. Он заменяет конструкции вроде `{{ product.name }}`
на реальное название товара. `{% for product in products %}` повторяет блок для
каждого товара. `{% if ... %}` показывает блок только при выполнении условия.

## 3. Что происходит при запуске

1. `start.bat` переходит в папку проекта и выбирает Python из `.venv`.
2. Python выполняет `app.py` и импортирует нужные функции из двух других файлов.
3. `app = Flask(__name__)` создаёт приложение. `__name__` помогает Flask найти
   рядом папки `templates` и `static`.
4. `init_db()` создаёт таблицы, если их нет. При первом создании файла добавляет
   четыре демонстрационных товара. При последующих запусках данные не сбрасываются.
5. `@app.route(...)` и `@app.get(...)` связывают адреса с функциями.
6. `app.run(...)` начинает слушать запросы только на `127.0.0.1`.
7. Программа ждёт, пока вы откроете страницу или нажмёте кнопку.

`.venv` — отдельная папка с окружением Python и установленными библиотеками
этого проекта. Она нужна, чтобы запуск использовать с правильным Flask.
Вручную «активировать окружение» здесь не требуется: мы вызываем его Python напрямую.

## 4. Вход и роль пользователя

В `app.py` есть словарь `USERS` с двумя учебными пользователями.
При отправке формы Flask сравнивает логин и пароль со словарём.
Если данные верны, приложение записывает в `session` имя и роль пользователя.

`session` — данные текущего входа. Flask хранит их в подписанной cookie браузера.
Cookie — небольшой фрагмент данных, который браузер передаёт серверу с запросами.
Подпись помогает обнаружить подмену роли; содержимое сессии не является шифрованным.
Секретный ключ создаётся случайно при запуске, поэтому после перезапуска нужно войти снова.
На содержимое базы это не влияет. Пароль в сессию не записывается.

`@login_required` — наша проверка перед вызовом функции страницы.
Если пользователь не вошёл, его отправляют на `/login`.
`@wraps` сохраняет имя исходной функции, чтобы Flask правильно различал маршруты.
Для выхода мы очищаем сессию.

## 5. GET, POST, redirect и flash

**GET** просит показать страницу. Пример: открыть каталог или форму редактирования.

**POST** отправляет данные действия. Пример: сохранить товар или оформить заказ.
В HTML `method="post"` задаёт способ отправки, а `action` — адрес обработчика.
Атрибут `name` поля определяет ключ, по которому Python получает его значение:
`request.form.get('quantity')` читает поле с `name="quantity"`.

**redirect** отправляет браузер на другую страницу после сохранения. Так обновление
страницы после перехода не повторяет последний POST автоматически.

**flash** запоминает сообщение для следующей страницы: «Товар сохранён» или
«Количество должно быть целым числом». `base.html` выводит эти сообщения.

**url_for** строит адрес по имени Python-функции: `url_for('orders')` даёт `/orders`.

## 6. Как устроена база

Таблица похожа на лист Excel: столбцы — свойства, строки — отдельные записи.

### Таблица products

| Поле | Значение | Пример |
|---|---|---|
| id | Уникальный номер товара | 1 |
| name | Название | Игровая мышь |
| category | Категория | Мыши |
| price | Цена за одну штуку | 35.00 |

### Таблица orders

| Поле | Значение | Пример |
|---|---|---|
| id | Уникальный номер заказа | 1 |
| customer_name | Логин покупателя | student |
| product_id | Номер товара из products | 1 |
| quantity | Сколько штук заказали | 2 |
| total_price | Итоговая сумма на момент заказа | 70.00 |

`PRIMARY KEY` — уникальный номер записи. `AUTOINCREMENT` позволяет базе выдавать номер.
`NOT NULL` запрещает отсутствие значения. `CHECK` проверяет условие, например
`quantity > 0`. `FOREIGN KEY` связывает заказ с существующим товаром.
`ON DELETE RESTRICT` запрещает удалить товар, если на него ссылается заказ.
`PRAGMA foreign_keys = ON` включает проверку этих связей на каждом подключении.

`JOIN` на странице заказов соединяет две таблицы: в заказе лежит номер товара,
а его название берётся из `products`. Итог заказа хранится отдельно: изменение
цены товара не пересчитает старый заказ. Название старого заказа при этом покажет
текущее название товара — отдельный снимок названия здесь не хранится.

## 7. CRUD — четыре обычных действия

| Буква | Действие | Кнопка/страница | SQL |
|---|---|---|---|
| C: Create | Создать | Добавить товар | INSERT |
| R: Read | Прочитать | Каталог | SELECT |
| U: Update | Обновить | Редактировать | UPDATE |
| D: Delete | Удалить | Удалить товар | DELETE |

Для заказов по заданию реализованы создание и чтение. Редактирование и удаление
заказов не требуются в разделе CRUD Requirements PDF.

SQL — язык команд к базе данных. Например:

```sql
SELECT * FROM products WHERE id = ?
```

Это значит «получи все поля товара с заданным номером».
Знак `?` — место для параметра, который передаётся отдельно.
Так данные пользователя не склеиваются с текстом SQL-команды.
`fetchone()` возвращает одну запись, `fetchall()` — все найденные записи.
`row_factory = sqlite3.Row` позволяет обращаться к полю как `product['price']`.

В `database.py` функция `connect()` используется так:

```python
with connect() as db:
    db.execute('... SQL ...')
```

`with` открывает подключение, выполняет блок и закрывает его.
Внутри нашей функции при успешном выполнении SQLite делает commit — сохранение.
При исключении выполняет rollback — отмену несохранённых изменений.
`finally` гарантирует закрытие подключения и при успехе, и при ошибке.
`@contextmanager` позволяет оформить этот порядок как удобный блок `with`.

## 8. Proxy — посредник с проверкой прав

Паттерн — распространённый способ организовать код для определённой задачи.
Proxy переводится как «заместитель» или «посредник». Представьте охранника:
перед входом он проверяет, разрешено ли вам пройти.

В `patterns.py` класс `ProductProxy` имеет методы `list`, `get`, `add`, `edit`,
`delete`. Он хранит реальный объект `ProductRepository`, который выполняет SQL.
Для чтения Proxy сразу передаёт работу хранилищу. Для изменения сначала вызывает
`check_permission()`, затем — соответствующий метод хранилища.

```text
Добавить товар
  → app.py получает POST
  → ProductProxy.add(...)
  → check_permission(): роль admin?
       да → ProductRepository.add(...) → INSERT → store.db
       нет → PermissionError → ответ 403
```

`class` — описание типа объекта. `self` — конкретный созданный объект.
`__init__` вызывается при его создании. Вызов `ProductProxy('admin')` создаёт
посредника, которому известна роль администратора.

В `app.py` проверка также вызывается перед показом формы, чтобы покупатель
не получил даже страницу редактирования. Изменения идут через методы Proxy.
Скрытие кнопок в HTML делает интерфейс удобнее, но само по себе не защищает:
пользователь может отправить POST напрямую. Поэтому проверка находится в Python.

Это структурный паттерн, потому что он задаёт отношения объектов: посредник
предоставляет операции реального хранилища и управляет доступом к нему.

## 9. Facade — одна кнопка для нескольких шагов

Facade переводится как «фасад». Представьте сотрудника на стойке оформления:
вы передаёте ему запрос, а он организует все внутренние шаги.

В `app.py` обработчик заказа вызывает один метод:

```python
total = OrderFacade().place_order(
    session['username'], product_id, request.form.get('quantity', '')
)
```

Внутри `place_order()` выполняются шаги:

1. Проверить, что имя покупателя не пустое.
2. Превратить количество из текста формы в целое число.
3. Проверить допустимый диапазон количества.
4. Найти товар в базе; если его нет — сообщить об ошибке.
5. Взять цену из базы и умножить на количество.
6. Сохранить заказ в `orders`.
7. Вернуть сумму обработчику, который покажет сообщение.

Пример: мышь стоит 35, покупатель выбирает 2. Фасад рассчитывает `35 × 2 = 70`
и сохраняет заказ. Клиент не может назначить свою итоговую цену через форму:
сервер сам берёт правильную цену из базы.

`Decimal` используется для десятичных расчётов, чтобы избегать обычных погрешностей
двоичных `float`. `quantize(Decimal('0.01'))` округляет до двух знаков.
В SQLite цена хранится как REAL согласно заданию; расчёт делается через Decimal.

Facade отличается от Proxy задачей: **Facade объединяет несколько шагов,
Proxy проверяет доступ и передаёт вызов реальному объекту**.

## 10. Полный путь добавления товара

1. Администратор нажимает «Добавить товар».
2. Браузер отправляет GET `/products/add`.
3. Flask вызывает `product_form()`: вход и роль проверяются.
4. `render_template()` создаёт страницу из `product_form.html`.
5. Пользователь вводит название, категорию и цену, нажимает «Сохранить».
6. Браузер отправляет POST на тот же адрес.
7. Python проверяет непустые строки и допустимую цену. Проверки нужны и на сервере,
   потому что ограничения HTML можно обойти.
8. `ProductProxy.add()` проверяет администратора и обращается к хранилищу.
9. `ProductRepository.add()` выполняет INSERT; подключение сохраняет изменения.
10. Flask отправляет redirect на `/`; каталог повторно читает таблицу и показывает товар.

Редактирование устроено так же, но сначала читается текущий товар и выполняется UPDATE.
Удаление отправляет POST и выполняет DELETE. Если есть связанный заказ, база запрещает
удаление; исключение `sqlite3.IntegrityError` превращается в понятное сообщение.

## 11. Зачем отдельные файлы

`app.py` отвечает за общение с браузером. `database.py` — за хранение.
`patterns.py` — за правила доступа и оформление заказа. HTML отвечает за видимые
элементы, CSS — за оформление. Так можно найти нужную часть без поиска по огромному файлу.

`base.html` — общая рамка всех страниц: шапка, меню, сообщения, подключение CSS.
Остальные шаблоны используют `{% extends 'base.html' %}` и заполняют блок `content`.
Поэтому меню не копируется в каждую страницу.

## 12. Короткие ответы для защиты

**Что такое Flask?** Библиотека Python для веб-приложений: связывает запросы с функциями
и помогает отправлять HTML-страницы.

**Для чего SQLite?** Чтобы хранить товары и заказы между запусками в локальном файле.

**Где CRUD?** Добавление, каталог, редактирование и удаление товаров.

**Где Facade?** `OrderFacade.place_order()` в `patterns.py`: проверка, расчёт и сохранение
спрятаны за одним вызовом.

**Где Proxy?** `ProductProxy` в `patterns.py`: разрешает изменение товаров только admin
и передаёт выполнение объекту `ProductRepository`.

**Почему нельзя просто скрыть кнопки?** Запрос можно отправить вручную, поэтому сервер
обязан проверять роль независимо от видимости кнопки.

**Что происходит после перезапуска?** Данные остаются в `store.db`; требуется повторный вход.

**Как можно расширить проект?** Добавить таблицу пользователей, остатки товаров,
корзину с несколькими товарами, статус заказа или учебную имитацию оплаты.
Эти улучшения не нужны для текущего минимального задания.
