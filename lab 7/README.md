# Лабораторная №7 — Smart Game Store

Простой локальный магазин по заданию Lab-7.pdf. Реализованы Python, Flask, SQLite,
HTML/CSS, CRUD товаров, оформление и просмотр заказов, Facade и Proxy.
Весь интерфейс на русском языке. Регистрация, платежи и складские остатки не входят
в этот минимальный вариант: в основных требованиях PDF их нет.

## Запуск на этом компьютере

1. Дважды нажмите **start.bat** в папке проекта.
2. Оставьте появившееся окно открытым.
3. Откройте браузер и введите **http://127.0.0.1:5000**.
4. Войдите одной из учебных учётных записей:

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | admin | admin123 |
| Покупатель | student | student123 |

Чтобы остановить приложение, нажмите **Ctrl+C** в окне запуска.
После повторного запуска товары и заказы сохраняются. Войти потребуется снова.
Flask уже установлен в `.venv` этой папки. Для ежедневного запуска интернет не нужен.
Никаких аккаунтов в сторонних сервисах, Docker, MySQL или облачного хостинга не требуется.

Если предпочитаете терминал PowerShell, откройте его в папке проекта:

```powershell
.\.venv\bin\python.exe app.py
```

Здесь установлен Python из MSYS2, поэтому окружение использует папку `bin`.
На обычном Windows Python это `Scripts`; `start.bat` учитывает оба варианта.

## Установка на другом компьютере

Нужны Python 3.10+ и браузер. Редактор VS Code или PyCharm удобен для чтения кода,
но для запуска не обязателен. Не переносите `.venv` между компьютерами: создайте новое окружение.
Для обычного Windows Python выполните в папке проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Скачивание Flask нужно только при установке. Flask — библиотека внутри Python,
а не внешний сервис. SQLite уже входит в Python и хранит данные в файле `store.db`.

## Что показать преподавателю

1. Войдите как `admin`: покажите четыре исходных товара.
2. Добавьте товар «Тестовая мышь», категория «Мыши», цена `10`.
3. Нажмите «Редактировать», измените цену на `12.50`, сохраните.

5. Выйдите и войдите как `student`. Кнопок управления товарами нет.
6. Введите прямо в адресную строку `http://127.0.0.1:5000/products/add`.
   Сервер покажет отказ в доступе. Это демонстрация Proxy.
7. Вернитесь к товарам. Закажите две игровые мыши по $35.
   В заказах появится сумма **$70.00**. Это демонстрация Facade.

9. Войдите как `admin`: все заказы доступны администратору.
10. Попробуйте удалить игровую мышь, которая есть в заказе:
    приложение объяснит, что удаление запрещено для сохранения истории.

## Где сохраняется информация о товарах и заказах

Все рабочие данные сохраняются **на этом компьютере в файле `store.db` рядом
с `database.py` и `app.py`**. Полный путь в вашей папке:

```text
C:\Users\shahk\OneDrive\Рабочий стол\lab 7\store.db
```

Место определяется в `database.py` строкой:

```python
DB_PATH = Path(__file__).with_name('store.db')
```

`__file__` — путь к самому `database.py`, а `with_name('store.db')` выбирает файл
базы в той же папке. Поэтому расположение базы не зависит от того, из какой папки
терминала вы запустили программу. `store.db` — двоичный файл SQLite, а не обычный
текстовый документ: открытие в текстовом редакторе не покажет удобную таблицу.
Приложение не отправляет данные внешним сервисам. При этом сама папка проекта
находится внутри OneDrive: её синхронизация зависит от настроек OneDrive в Windows.

### Что именно записывается при каждом действии

| Действие | Где находится код | Что меняется в `store.db` |
|---|---|---|
| Добавление товара | `ProductRepository.add()` в `database.py` | Команда `INSERT` добавляет строку в `products`: номер, название, категория, цена |
| Редактирование товара | `ProductRepository.edit()` в `database.py` | Команда `UPDATE` меняет поля существующей строки в `products` |
| Удаление товара | `ProductRepository.delete()` в `database.py` | Команда `DELETE` удаляет строку из `products`, если товар не связан с заказами |
| Добавление заказа | `OrderFacade.place_order()` в `patterns.py` | Команда `INSERT` добавляет строку в `orders`: номер заказа, логин покупателя, номер товара, количество, итоговая сумма |
| Просмотр заказов | `orders()` в `app.py` | `SELECT` и `JOIN` читают существующие данные; новые записи не создаются |
| Удаление заказа | В текущем приложении не реализовано | Кнопки и обработчика удаления заказов нет; заказ остаётся в `orders` |

Один заказ в этой версии — один вид товара и его количество. Например, две мыши
по $35 создают одну строку: `customer_name = student`, `product_id = 1`,
`quantity = 2`, `total_price = 70`. Номер заказа `id` база назначает автоматически.
Заказ сохраняется сразу при успешном оформлении, без отдельной кнопки сохранения базы.

### Как заказ проходит от кнопки до файла

```text
Кнопка «Оформить заказ» в templates/products.html
    → POST /orders/add/<номер товара>
    → add_order() в app.py
    → OrderFacade.place_order() в patterns.py
    → проверка количества и поиск товара в products
    → расчёт суммы по цене из базы
    → INSERT INTO orders (...)
    → успешный выход из with connect(): commit
    → данные сохранены в store.db
    → переход на /orders и показ сохранённого заказа
```

`connect()` в `database.py` управляет подключением к SQLite. Внутри него
`with connection` подтверждает изменения при успешном завершении блока — это
называется **commit**. Если в блоке возникает исключение, неподтверждённые изменения
отменяются — **rollback**. В `finally` подключение закрывается.

После закрытия браузера или остановки Python данные остаются в `store.db`.
Повторный запуск `init_db()` создаёт только недостающие таблицы и не очищает заказы.
Для резервной копии остановите приложение и скопируйте `store.db` в другую папку.
Файл базы хранит данные, а файлы `.py` — правила работы с ними.

### Сохраняется ли история добавлений и удалений

**Отдельный журнал действий в этой версии не ведётся.** Есть текущее содержимое
таблиц, но нет таблицы истории, даты действия или записи «кто и когда удалил товар».

- При добавлении заказа сохраняется сам заказ и логин покупателя. Дата создания
  и отдельное событие «заказ добавлен» не сохраняются.
- При успешном удалении товара его строка удаляется. Отдельной записи об удалении
  нет, а восстановление через интерфейс не предусмотрено.
- Если товар уже используется в заказе, ограничение `ON DELETE RESTRICT` запрещает
  удаление. `delete_product()` в `app.py` перехватывает `sqlite3.IntegrityError`
  и показывает объяснение. Товар и заказ остаются в базе.
- Сообщение `flash('Товар удалён.')` — временное уведомление на странице,
  а не постоянная запись в журнале.
- Строки GET/POST в терминале Flask — журнал HTTP-запросов. Они не заменяют историю
  изменений базы и не записываются этим приложением в отдельный файл.

Таким образом, на защите правильно сказать: **«Сохраняются товары и заказы,
но аудит всех действий и удаление заказов в минимальной версии не реализованы»**.

### Как посмотреть сохранённую информацию

Самый простой способ — открыть сайт: «Товары» показывает таблицу `products`,
«Заказы» — данные `orders` с названиями из `products`. Администратор видит все
заказы, покупатель — только заказы со своим логином.

Чтобы увидеть именно строки базы без установки дополнительных программ,
выполните в терминале VS Code из папки проекта:

```powershell
.\.venv\bin\python.exe -c "from database import connect; db = connect(); conn = db.__enter__(); print('PRODUCTS:'); print([dict(row) for row in conn.execute('SELECT * FROM products')]); print('ORDERS:'); print([dict(row) for row in conn.execute('SELECT * FROM orders')]); db.__exit__(None, None, None)"
```

Команда только читает данные и выводит их в терминал. Упрощённые таблицы и описание
каждого поля также приведены в `EXPLANATION.md`.

## Подробный текст защиты: паттерны, их место и причина выбора

Ниже — текст, который можно рассказывать, одновременно открывая указанные файлы.

### 1. Представление проекта

«Моя лабораторная работа — локальное веб-приложение Smart Game Store.
Я использовал Python для логики, Flask для обработки запросов, SQLite для хранения
данных, HTML для страниц и CSS для оформления. Все товары и заказы хранятся в файле
`store.db`. Администратор может добавлять, просматривать, редактировать и удалять
товары. Покупатель может просматривать товары и оформлять заказы.

В работе использованы два структурных паттерна: **Proxy, или Заместитель**, и
**Facade, или Фасад**. Они выбраны для двух конкретных задач: ограничения доступа
к управлению товарами и упрощения оформления заказа».

### 2. Proxy: где он реализован

**Откройте `patterns.py` и покажите класс `ProductProxy`. Затем откройте
`database.py` и покажите класс `ProductRepository`.**

«Паттерн Proxy реализован классом `ProductProxy` в файле `patterns.py`.
Реальный объект, который работает с товарами в базе, — `ProductRepository`
в файле `database.py`. У обоих есть методы `list`, `get`, `add`, `edit` и `delete`.
Proxy предоставляет эти операции, но перед изменениями проверяет права.

В конструкторе Proxy получает роль пользователя и создаёт объект хранилища:

```python
def __init__(self, role):
    self.role = role
    self.repository = ProductRepository()
```

Для добавления товара используется такой порядок:

```python
def add(self, name, category, price):
    self.check_permission()
    self.repository.add(name, category, price)
```

Сначала `check_permission()` сравнивает роль с `admin`. Если роль другая,
возникает `PermissionError`, и вызов хранилища не выполняется. Если это
администратор, Proxy передаёт работу в `ProductRepository.add()`, а тот выполняет SQL.
Аналогично защищены `edit()` и `delete()`. Для просмотра `list()` и `get()` проверка
администратора не требуется: читать товары может и покупатель после входа».

**Теперь в `app.py` покажите `product_proxy()`, `product_form()`,
`delete_product()` и обработчик `forbidden()`.**

«В `app.py` функция `product_proxy()` берёт роль из сессии и создаёт посредника.
Обработчики управления товарами используют его вместо прямого вызова SQL.
Дополнительный вызов `proxy.check_permission()` перед показом формы запрещает
покупателю даже открыть форму добавления или редактирования.
При запрете обработчик `forbidden()` возвращает страницу с кодом HTTP 403».

```text
Запрос управления товаром
    → app.py
    → ProductProxy: проверка роли
        → admin: ProductRepository → SQL → store.db
        → customer: PermissionError → HTTP 403
```

### 3. Почему выбран именно Proxy

«Мне нужно было сохранить обычные операции над товарами, но добавить проверку
доступа перед их выполнением. Для этого подходит **защитный Proxy**: он стоит между
обработчиком запроса и реальным хранилищем и решает, разрешено ли передать вызов.

Проверка прав собрана в одном месте, поэтому правила не приходится отдельно
переписывать внутри каждого SQL-метода. Хранилище отвечает за данные, а посредник —
за доступ. Если правило изменится, я смогу изменить `check_permission()`.

Одного скрытия кнопок недостаточно: пользователь может вручную отправить запрос.
Поэтому проверка выполняется на сервере. При демонстрации я войду как `student`
и открою `/products/add`: сервер откажет, хотя адрес введён напрямую».

Уточнение для вопроса преподавателя: `ProductRepository` сам не проверяет роль.
Поэтому новые обработчики управления товарами тоже должны обращаться через Proxy.
В текущих обработчиках это правило соблюдено.

### 4. Facade: где он реализован

**Откройте `patterns.py` и покажите `OrderFacade.place_order()`.
Затем в `app.py` покажите `add_order()`.**

«Паттерн Facade реализован классом `OrderFacade` в файле `patterns.py`.
Его метод `place_order()` предоставляет один простой вход для оформления заказа.
Обработчику Flask не нужно самостоятельно выполнять весь процесс:

```python
total = OrderFacade().place_order(
    session['username'], product_id, request.form.get('quantity', '')
)
```

Фасад принимает логин покупателя, номер товара и количество. Затем он:

1. Проверяет, что логин не пустой.
2. Проверяет, что количество — целое число от 1 до 10 000.
3. Ищет товар в базе и убеждается, что он существует.
4. Берёт цену из базы и рассчитывает сумму через `Decimal`.
5. Выполняет `INSERT` в таблицу `orders`.
6. После сохранения возвращает рассчитанную сумму.

Например, при заказе двух мышей по $35 фасад рассчитывает $70 и сохраняет одну
строку заказа. Цена берётся с сервера, поэтому переданное из браузера произвольное
значение итоговой суммы не используется».

```text
add_order() в app.py
    → один вызов OrderFacade.place_order(...)
        → проверка данных
        → чтение товара из SQLite
        → расчёт суммы
        → запись заказа в SQLite
    ← итоговая сумма
    → сообщение и переход к списку заказов
```

### 5. Почему выбран именно Facade

«Оформление заказа состоит из нескольких последовательных действий, но для
обработчика страницы это одна операция — “оформить заказ”. Facade позволяет
представить этот процесс одним методом и скрыть внутренние шаги.

Благодаря этому `add_order()` отвечает за веб-часть: получает данные формы,
вызывает фасад и выбирает, какую страницу показать. Проверка заказа, расчёт и запись
сосредоточены в `place_order()`. Такой метод можно вызвать из другого обработчика
или теста, не копируя весь процесс оформления.

В этой небольшой работе фасад объединяет простые проверки, расчёт и обращения
к SQLite непосредственно внутри метода. Создавать отдельный класс для каждого
шага не потребовалось — это сохранило лабораторную понятной».

### 6. Чем паттерны отличаются и как связаны с базой

| Вопрос | Proxy | Facade |
|---|---|---|
| Какую задачу решает? | Проверяет, можно ли выполнить операцию с товаром | Организует несколько шагов оформления заказа |
| Где находится? | `patterns.py`, класс `ProductProxy` | `patterns.py`, класс `OrderFacade` |
| Главные методы | `check_permission()`, `add()`, `edit()`, `delete()` | `place_order()` |
| С чем работает? | Делегирует операции `ProductRepository` | Проверяет данные, считает сумму и обращается к SQLite через `connect()` |
| Как показать результат? | Покупатель получает 403 при попытке управления | Две мыши по $35 дают сохранённый заказ на $70 |

«Оба паттерна структурные: они организуют взаимодействие частей программы.
Proxy добавляет посредника перед реальным объектом, а Facade даёт простой вход
к группе внутренних операций. Сам файл `store.db` не является паттерном — это
хранилище данных. Класс `ProductRepository` выполняет SQL, а `connect()` управляет
подключением и сохранением изменений.

Для выполнения задания я выбрал Facade и Proxy: именно они требуются в разделе
описания задачи PDF и решают реальные задачи этого магазина. Для демонстрации
этих двух задач Flyweight и Private Class Data не понадобились».

### 7. Как завершить защиту

«Таким образом, я реализовал полный CRUD товаров и создание и просмотр заказов.
Данные сохраняются локально в SQLite и остаются после перезапуска. Proxy защищает
изменение товаров на сервере, а Facade собирает оформление заказа в один метод.
Товар, участвующий в заказе, защищён от удаления внешним ключом базы.
Отдельный журнал действий, удаление заказов и настоящая оплата в минимальную
версию не входят. Проверки прав, CRUD, суммы заказа и неверного ввода покрыты
автоматическими тестами».

Тесты проверяют CRUD, права, расчёт суммы, неверный ввод, сохранение после
повторной инициализации, вход и выход. Настоящие товары и заказы не изменяются.

## Если что-то не запускается

| Проблема | Решение |
|---|---|
| Браузер не открывает сайт | Сначала запустите `start.bat`, окно должно оставаться открытым |
| `No module named flask` | Используйте Python из `.venv`, а не системный `python` |
| `python` не найден на другом ПК | Установите Python и включите Add Python to PATH |
| Порт 5000 занят | Закройте прошлое окно запуска; либо задайте другой порт командой ниже |
| Отказ в доступе к управлению | Войдите как `admin`, покупатель имеет ограниченные права |
| Товар не удаляется | Он связан с заказом; это ограничение базы, а не поломка |

Другой порт в PowerShell:

```powershell
$env:PORT = '5001'
.\.venv\bin\python.exe app.py
```

После этого адрес — `http://127.0.0.1:5001`.
Это учебное локальное приложение: две демонстрационные учётные записи заданы в коде.
